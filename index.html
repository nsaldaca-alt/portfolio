2 apps · isolated data · 1 sign-in · 1 help desk

BOps · back-office finance

241 commits · ~42k lines · 56 models
  • Invoices: expense and sales invoices from upload, bulk zip import or a monitored mailbox, with duplicate checks, extraction and an approval step.
  • Treasury: a weekly, monthly and yearly cash projection. Every cell is computed from invoice and debt data, and the balance is anchored to real bank balances.

Prisier One · client portal

168 commits · ~28k lines · ~740 tests

  • API and MCP: a token REST API and an MCP server let staff publish deliverables from scripts and AI agents.
  • Operations: scheduled maintenance windows, release notices, bulk account creation and audited deletes behind three confirmations.

4)Security hardening · built for financial and personal data

OWASP ASVS Level 2 review

Identity and access

  • Microsoft Entra single sign-on for staff. Users are matched on an immutable ID and accounts are never created automatically.
  • Roles live in the app's own database: one permission matrix, checked on every request and restated in tests.
  • Separate rights for exporting data, scoped per partner.

Data protection

  • Personal and payroll data encrypted at the column level with a dedicated key. Without the key the module refuses to serve, so it never falls back to plain text.
  • Legal documents stored with envelope encryption (AES-GCM).
  • Client data kept on separate database, storage and key-vault resources. Both apps hosted in Brazil South for Latin American data residency.

Application and integrations

  • Strict content security policy with zero inline scripts; I moved 128 inline handlers to remove the last exception.
  • API tokens expire, can be scoped to one project and are stored only as hashes. The API is off by default and every action is audited.
  • Least privilege on integrations: mailbox access is limited to one mailbox (verified: allowed there, refused elsewhere), the accounting API is read-only, and the help desk queries the database in read-only transactions.

5)Analytics · Pricing for a national apparel retailer

Prisier client · Mar 2026

For a Prisier client with more than 230 stores in four countries, I analysed a full year of sales: 6.2M transaction lines in a 1.3 GB file, in Python (pandas, NumPy, matplotlib).

The client's name and figures are confidential and left out on purpose.

  • Normalised mixed currencies and stores that record order totals instead of per-unit prices.
  • Computed margin per transaction and broke it down by country, store, channel, product line and month.
  • Found that 2.1% of transactions were sold below cost, and traced the losses to a few stores where 86–98% of sales carried a deep discount.
  • Delivered 10 charts, written reports and a presentation.
